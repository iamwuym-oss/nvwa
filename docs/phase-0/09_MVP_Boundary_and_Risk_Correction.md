# Nüwa Backup — MVP Boundary & Risk Correction

**版本：** v1.0
**日期：** 2026-07-05
**状态：** 生效 — 作为所有 Phase 1 决策的边界依据

---

## 1. MVP 核心定义

### 1.1 MVP 目标

构建一个**最小可验证的文件级备份/恢复闭环**，不包含卷、磁盘、VSS、WinPE、daemon、UI、差异、克隆、异机还原。

### 1.2 MVP 验收标准

`
用户操作：
  用户选择一个本地文件夹 → 点击"备份" → 备份完成
  用户选择一个备份点 → 点击"恢复" → 文件恢复到指定位置

验收条件：
  恢复后的文件与源文件 SHA-256 一致
  批量小文件（1000+）正确处理
  大文件（10GB+）正确处理
  特殊字符文件名正确处理
  备份过程中程序崩溃 → 不破坏已有的可用备份
  目标盘空间不足 → 优雅提示，不产生半截备份
`

### 1.3 MVP 范围

| 项目 | 包含 | 不包含 |
|------|------|--------|
| 备份类型 | 完整备份 (Full)  | 差异、增量、持续 |
| 备份粒度 | 文件/文件夹 | 卷、磁盘、分区 |
| 目标位置 | 本地副盘、USB | NAS、NFS、本机同盘 |
| 调度 | 手动触发 | 定时、开机、登录、USB 插入 |
| 格式 | 平文件存储（非 .nwb）| .nwb 镜像格式 |
| 压缩 | 可选（zstd 单线程）| 多线程压缩池、自适应压缩 |
| 校验 | SHA-256 文件级 | xxHash3 块级、XOR parity |
| 加密 | 不实现 | AES-256-GCM |
| 恢复 | 文件级恢复到原位置/新位置 | 卷级、系统级、裸机、异机 |
| CLI | 最小命令集 | daemon、IPC、完整命令体系 |
| GUI | 不实现（Phase 2）| egui 桌面应用 |
| OS 范围 | Win10/Win11/Win Server 2019/2022 | Win7/8/Server 2008/2012 |

## 2. 风险清单

### 2.1 高风险项

| 风险 ID | 风险描述 | 缓解措施 |
|---------|---------|---------|
| R-001 | 备份过程中源文件被修改，导致备份与源不一致 | 第一阶段明确告知用户"建议关闭正在编辑的文件"，不做文件锁 |
| R-002 | 大文件（10GB+）备份过程中断，产生不完整备份 | 实现原子写入：先写 .tmp，完成后重命名 |
| R-003 | 目标盘空间耗尽，备份写一半失败 | 备份前校验目标盘剩余空间，预留 10% 安全余量 |
| R-004 | 用户误将备份目标选为源盘 | 源路径与目标路径完全相同时禁止操作 |
| R-005 | 恢复时覆盖了用户还在使用的文件 | 恢复前检查文件是否被占用，锁定的文件跳过并提示 |

### 2.2 中风险项

| 风险 ID | 风险描述 | 缓解措施 |
|---------|---------|---------|
| R-006 | 批量小文件（1000+）备份性能差 | 第一阶段接受性能瓶颈，不做批量优化 |
| R-007 | 文件名含特殊字符/超长路径 | 第一阶段标记已知限制：Windows MAX_PATH 260 字符 |
| R-008 | 文件权限导致备份或恢复失败 | 需要管理员权限运行，启动时检查并提示 |
| R-009 | 备份元数据损坏后无法找到备份 | 使用独立的元数据清单文件 + SHA-256 校验 |

### 2.3 低风险项

| 风险 ID | 风险描述 | 缓解措施 |
|---------|---------|---------|
| R-010 | 中文/Unicode 文件名处理 | Rust 原生 UTF-8，Windows API 使用 W 版本 |
| R-011 | 隐藏文件和系统文件处理 | 默认包含，提供排除清单机制 |
| R-012 | 符号链接/硬链接/挂载点 | 第一阶段不跟踪链接，按普通文件处理 |

## 3. 明确禁止的前置实现清单

以下功能在 MVP 阶段（Phase 1）严禁实现：

- 差异备份 / Differential Image
- .nwb 镜像格式（Phase 2 实验格式）
- VSS 快照
- NTFS  / 智能块识别
- GPT/MBR 分区表
- 系统卷备份
- WinPE / 启动介质
- 裸机恢复 / 异机还原
- 驱动注入
- 磁盘克隆
- lcb-daemon 系统服务
- ZeroMQ IPC
- 桌面 GUI（egui）
- AES 加密
- XOR Parity
- NFS
- SMTP 邮件通知
- Linux / 国产 OS / LoongArch
- BitLocker / ReFS
- ext4 / XFS / btrfs 智能识别
- 性能管线优化目标

## 4. 被降级为 Future 的功能清单

| 功能 | 原设定阶段 | 现设定阶段 | 降级原因 |
|------|-----------|-----------|---------|
| 差异备份 | Phase 1 | Future (Phase 5+) | USN Journal + 块映射过于复杂，不能作为第一版正确性基础 |
| .nwb 镜像格式 | Phase 1 | Phase 2 | 格式设计过早复杂化，应先以平文件存储验证备份/恢复闭环 |
| XOR Parity | Phase 1 | Future (Phase 5+) | 增加实现复杂度，MVP 只需要校验检测 |
| AES 加密 | Phase 1 | Future (Phase 4+) | MVP 不处理敏感数据场景 |
| VSS 快照 | Phase 1 | Phase 3 | Phase 1 不需要系统卷一致性 |
| lcb-daemon | Phase 1 | Phase 3 | CLI 直连即可完成 MVP |
| 桌面 GUI | Phase 2 | Phase 2（不变）| 但移到 Phase 2 中后期 |
| 性能优化目标 | Phase 1 | Phase 2+ | MVP 以正确性优先，速度可接受即可 |
| Win7/Server 2008 | Phase 1 | Phase 2+ | MVP 验证平台优先 Win10+ |
| NFS | Phase 1 | Phase 5+ | 网络存储场景复杂，SMB 优先 |

---

## 5. MVP 合规要求

1. **所有完成标准以恢复验证为准**
2. **性能不作为 MVP 验收标准**
3. **数据完整性高于备份速度**
4. **不允许任何隐藏的"未实现但文档标记为实现"的功能**
5. **所有文档中的阶段描述必须一致**
6. **缺失的功能要在文档中明确标记为"当前阶段不实现"或"Future"**
