## 1. 整体设计理念

### 1.1 性能设计目标

| 指标 | 目标 | 参考基准 |
|------|------|---------|
| 全量备份速度 (SSD→SSD) | ≥ 500 MB/s | Acronis TI on 12th-gen Intel |
| 恢复速度 (SSD→SSD) | ≥ 600 MB/s | 目标盘写入速度的 90% |
| 差异备份加速比 | ≥ 50x | 1% 变化量场景 |
| CPU 占用可配置 | 1~N 核 | Acronis "性能设置" |
| I/O 占用可配置 | 限制读取/写入速度 | Acronis "备份速度限制" |

### 1.2 管线的设计哲学

所有现代备份引擎的核心都是**不让任何资源空闲**。Acronis 的管线设计大致可概括为：

> **"用 CPU 的速度喂饱 I/O，用 I/O 的速度喂饱 CPU，双方谁也不能等谁。"**

具体来说：
- 读取线程：从 VSS 读取原始块，放入队列 → 立即去读下一块
- 压缩线程：从队列取块，压缩 + 校验 → 放入输出队列
- 写入线程：从输出队列取压缩数据，批量写入文件

三段完全流水线化，互不阻塞。

## 2. 管线架构（Pipeline Architecture）

### 2.1 备份管线

```
┌──────────────────────────────────────────────────────────────────┐
│                         BACKUP PIPELINE                          │
│                                                                  │
│  Reader (1 线程)                                                  │
│  ┌────────────────────────────────────┐                          │
│  │ 从 VSS 快照设备读取原始块          │                          │
│  │ Block Size: 64KB (用户可选倍增至64MB)│                        │
│  │ 预读策略: 顺序读 + 64MB 环形缓冲   │                          │
│  │ 输出: Vec<u8> (所有权转移,零拷贝)   │                          │
│  └────────────┬───────────────────────┘                          │
│               │ mpsc channel (64 槽)                            │
│               ▼                                                   │
│  Compression Pool (N 线程, N=cpu_cores)                          │
│  ┌────────────────────────────────────┐                          │
│  │ Reader 线程池取块                  │                          │
│  │ 1. 检测预分析：已压缩?→直写缓存    │                          │
│  │ 2. 全零?→标记空洞                  │                          │
│  │ 3. zstd 压缩 (级别可配)            │                          │
│  │ 4. xxHash3-64 快速校验             │                          │
│  │ 5. SHA-256 强校验                  │                          │
│  │ 输出: (orig_offset, comp_data,     │                          │
│  │        raw_sha256, is_sparse)      │                          │
│  └────────────┬───────────────────────┘                          │
│               │ mpsc channel (32 槽)                            │
│               ▼                                                   │
│  Writer (1 线程)                                                  │
│  ┌────────────────────────────────────┐                          │
│  │ 累积压缩块到 4MB 缓冲区            │                          │
│  │ 达到 4MB → WriteFile() 写入 .nwb   │                          │
│  │ 记录 Block Index Entry             │                          │
│  │ Group 完成 → flush + fsync         │                          │
│  └────────────────────────────────────┘                          │
│                                                                  │
│  内存占用控制:                                                     │
│    · Reader Ring Buffer: 64MB                                     │
│    · Channel Buffer: ~ (64 + 32) × 64KB ≈ 6MB                    │
│    · Writer Batch Buffer: 4MB                                     │
│    · 总峰值: ~75MB                                                │
└──────────────────────────────────────────────────────────────────┘
```
